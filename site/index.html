01 / FUNNEL EVIDENCE

Measure the journey.
Respect the denominator.

The primary funnel counts sessions that reach each stage in strict timestamp order. User reach counts distinct observed users at each event, without assuming a sequence.

  • View item → add to cart → begin checkout → purchase
  • Equal timestamps do not establish event order.
  • Device, country, source / medium, and visitor-proxy comparisons use minimum samples.
  • All stages were observed; strict ordering excludes tied or missing transitions.

4,848 sessions contained a purchase event; the strict funnel counts only complete ordered journeys.

PRODUCTION DATA SCIENCE EXTENSION

From session context to calibrated probabilities.

A first-product-view feature mart supports logistic regression and histogram gradient boosting. November training, separate December calibration and selection windows, and a final January test keep evaluation chronological.

Prediction-time features

BigQuery/dbt features use only early session context and behavior. Purchase outcomes, later events and raw identifiers cannot enter the estimator.

Model quality over time

PR-AUC, Brier score, log loss, reliability buckets, segment diagnostics and weekly drift artifacts accompany the fitted models.

Verification boundary

The complete modeling workflow passes local synthetic tests. Real GA4 model metrics and Linux Airflow runtime evidence are still pending. No model scores are claimed here.

Implemented path: staging → feature mart → validation → training → temporal evaluation and calibration → segment and weekly health → BigQuery result tables and a local model report. The existing analytics branch remains in place. Airflow coordinates both through a manual, parameterized replay.

11 / LIMITATIONS

What this evidence cannot tell us.

Obfuscation
Google warns that placeholders and limited internal consistency affect this export. It cannot be reconciled with the Analytics demo account.

Identity & time
Pseudonymous users are browser identifiers. The source window truncates earlier history and later returns; event dates and UTC timestamps have different roles.

Association & causality
Device, acquisition, and first-session behavior are observed characteristics. There is no randomized treatment assignment or causal product lift in these data.

Transaction scope: 906 purchase events have invalid transaction IDs. 15 conflicting IDs (33 events) are quarantined. Published revenue is the accepted, deduplicated subset, not total store revenue. Purchase-event conversion keeps its own denominator.

Refund, performance, and bounce-like guardrails are not assumed available. Source freshness is a documented production extension, not a historical alert.
